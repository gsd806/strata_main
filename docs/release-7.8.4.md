# STRATA 7.8.4 — Direct sole-owner administration

Build 7.8.4 removes redundant credential and typing steps from the private Admin area without adding another administrator or weakening its server authorization boundary. The one verified account permanently bound as primary owner opens Admin with its normal live account session.

## What changed

- **No separate step-up.** Admin no longer asks the already signed-in owner for a second password, sends an Admin email code, or creates a timed elevation window. The retired elevation endpoints are not active.
- **One clear review.** Account actions retain one explicit review dialog. The owner no longer types commands such as `SUSPEND`, an email address, or a separate audit explanation.
- **Server-owned audit context.** Each allowlisted action maps to a bounded, action-specific reason generated by the server. Obsolete client `confirmation` and `reason` values are not trusted or recorded.
- **The owner boundary remains narrow.** Admin still requires the verified, unsuspended account permanently bound to the primary-owner slot and its current unexpired session and credential version. An empty binding claim still forces a fresh sign-in.
- **Mutation defenses remain layered.** Trusted-Origin, CSRF, JSON-content, request-rate, action-allowlist, target, revision, and primary-owner self-protection checks remain. Hidden private data is purged before foreground or BFCache revalidation, and delayed responses cannot repaint a locked view.
- **Deletion remains guarded.** Direct deletion still pauses a non-owner account, revokes its sessions, reconciles unfinished checkout work, and refuses active or uncertain billing. The final database write atomically rechecks the acting owner session and auth version, protected target state, purchase and checkout blockers, and matching audit record.

Self-service account deletion is unchanged: it still uses the registered-email link and its own explicit confirmation. Strata+ pricing, Paddle configuration, entitlement behavior, account sessions, support storage, and workout/plan formats are also unchanged.

## Architecture

The Admin server coordinator is 209 physical lines and depends only on access-control state, the administrator user-action boundary, and plan validation. The Admin browser coordinator is 203 lines, with focused state (53), logic (88), API (45), rendering (189), session (53), and event (53) modules. The full enforced graph contains 40 server modules and 67 unique browser modules across 71 policy entries, with zero dependency cycles or policy violations.

The SQLite and Turso access-control and permanent-deletion predicates no longer depend on a separate elevation row. They still validate the permanently bound, verified, unsuspended owner, the exact live session token, matching current auth version, and session expiry at the guarded storage write. Optimistic revisions, billing predicates, and atomic audit behavior remain unchanged.

## Deployment and rollback

No database migration, secret, email-provider, or Paddle catalog change is required. Deploy the Node server and public Admin assets from the same commit. Sign in as the bound owner and verify that Admin opens directly; verify a non-owner is denied; then exercise a reversible account action and confirm its server-generated reason appears in the redacted audit trail.

Rollback is a redeploy of Build 7.8.3 and its matching public assets. The retained database structures remain compatible with that earlier elevation flow, and this release does not alter member-owned data formats.
